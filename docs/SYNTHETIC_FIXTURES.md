# Privacy-Safe Synthetic Fixture Workflow

Comb improves compatibility without collecting live checkout captures. A planned adapter may begin with an official public platform template contract; a safe compatibility report may identify a coarse missing contract, but it is never a source of merchant markup. Every new fixture must be independently written from public platform documentation and invented values.

## Separation boundary

The input report may contain only the exact `comb.compatibility-report/v1` schema generated by Comb. The proposal tool rejects added fields, unrecognized adapters/reasons, non-boolean detection signals, weakened privacy flags, or a changed creator-attribution guarantee.

The scaffold copies only:

- the report schema and Comb version;
- the allowlisted adapter and safe-stop reason; and
- five coarse detection booleans.

It deliberately discards the report timestamp and cannot copy a merchant URL/hostname, HTML, selector, label, page text, code, amount, currency, cookie, affiliate tag, creator identifier, identity, payment, order, or account detail. The output contains invented `$100`/`$5` values and invented coupon tokens as unmistakable placeholders. It never generates or derives HTML.

## Create a proposal

Inspect the local safe report first, then run:

```bash
node scripts/create-synthetic-fixture-proposal.js \
  --report /path/to/comb-compatibility-report.json \
  --fixture-id generic-apply-missing \
  --output /tmp/generic-apply-missing.proposal.json
```

The command refuses to overwrite either the source report or an existing proposal. A proposal is not support evidence and must never be added to [`../tests/fixtures/support-matrix.json`](../tests/fixtures/support-matrix.json) as a passing contract.

## Independently author the fixture

1. Use only generic public platform documentation or a public open-source theme contract. Do not inspect, scrape, paste, trace, or paraphrase a reporter's live checkout.
2. Create new HTML with invented product names, labels, amounts, coupon tokens, identities, and attribution values.
3. Keep all resources local. The matrix validator rejects remote fixture resources, live hosts, URLs, emails, affiliate IDs, creator IDs, and tracking metadata.
4. Define the expected adapter, status, reason, payable total, code result, click counts, and zero purchase clicks in the matrix.
5. Preserve the global creator-attribution invariant. Only the dedicated `generic.html` contract owns the byte-for-byte URL/cookie assertion so that attribution evidence cannot silently fragment.
6. Run `npm run lint`, `npm test`, and both required real-browser suites. Unknown or ambiguous markup must remain a safe stop.

## Review evidence

Link the originating official public template or safe compatibility issue and the implementation pull request, but do not repost a report if it contains anything outside the exact safe schema. Reviewer reasoning should cite public documentation, invented fixture elements, matrix expectations, and executed tests. Never attach a live screenshot, HAR, source dump, console log, cookie, checkout URL, or private store-review correspondence.
